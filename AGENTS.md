# Repository guidance

## Keep documentation synchronized

- Update `README.md`, including its first **Fork documentation** section, in the
  same change whenever features, behavior, settings, defaults, shortcuts, APIs,
  installation requirements, or development workflows affect the documentation.
- Keep the Fork documentation contents list synchronized with every subsection
  and its heading link. Check local links and Markdown formatting when editing.
- Verify documentation against the current implementation and relevant Git
  history. Describe final behavior, remove obsolete or superseded claims, and
  distinguish fork-specific changes from capabilities already present upstream
  (including patch-equivalent commits with different hashes).
- Reuse or link to existing detailed guides rather than duplicating them, and
  preserve unrelated README content and existing guidance.
- Do not make unnecessary README changes for implementation-only work that does
  not affect documented behavior, interfaces, requirements, or workflows.
